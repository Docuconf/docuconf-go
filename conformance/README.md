# docuconf conformance suite

Language-neutral test cases that every docuconf SDK runs (SPEC §12). Two
SDKs that disagree on a case cannot both be right, so the suite is how
"the platform and the app accept exactly the same values" is kept true
across languages.

| Path | What it is |
| --- | --- |
| `load/*.yaml` | The cases, written by hand. Edit these. |
| `cases.json` | Generated from `load/`. Every SDK's runner reads this file. Do not edit. |
| `fixtures/` | Certificates, keys and keystores the file cases use. Generated by `gen/`. Do not edit. |
| `gen/` | The Go program that writes `fixtures/`, deterministically: `go run ./conformance/gen` from the repository root. |
| `export/` | The shared export fixture: `fixture.yaml` describes the declaration, `golden.cue` is its contract. |

Regenerate `cases.json` after changing `load/` (the CLI's tests fail if it
is out of date):

```sh
cd cmd/docuconf && go run . conformance -dir ../../conformance
```

## Writing cases

A `load/*.yaml` file declares variables, as in a contract's `vars`, and a
list of cases:

```yaml
description: Integer variables (SPEC §4.3, §5).
vars:
  PORT: {type: int, description: Port to listen on, min: 1, max: 65535, default: 8080}
cases:
  - name: typed values          # what the platform sends
    values: {PORT: 9090}
  - name: below min             # what the app might see anyway
    env: {PORT: "0"}
    errors: [{var: PORT, code: out_of_range}]
  - name: empty is unset
    env: {PORT: ""}
    expect: {PORT: 8080}
```

- **`values`**: typed platform values. They must pass `#Validate`. The
  generator renders them with `#Render` into the environment the pod gets,
  and derives the expected result from the values and the defaults. A
  values case runs once per list encoding (`csv`, `json`, `indexed`) and
  duration encoding (`go`, `iso8601`, `seconds`, `timespan`) for each list
  or duration variable it sets whose encoding the file leaves open. Limit
  that with `only: {list: [json, indexed]}`.
- **`env`**: the raw environment, as strings, for input the platform would
  never send. Give `expect` (the variables you care about; the rest are
  derived from defaults) or `errors`.
- **`requires`**: capability tags (below). Use them only where a host
  genuinely cannot do what the case tests, or for a transitional tag. A
  file may list `requires` at its top level too, for every case in it.

Keep each case to one problem per variable: SDKs may stop checking a
variable after its first violation.

### Files, profiles and overlays

A file may also declare the contract's `files`, `profiles` and
`overlays`, exactly as a contract does, and an `env` case may give
`files`: the content of each file the app finds, by absolute path.

```yaml
description: Config files (SPEC §4.6).
requires: [files]
vars: {}
files:
  main:
    type: config
    format: json
    description: Main settings, always present
    required: true
    path: /etc/app/main/main.json
    schema: {type: object, properties: {port: {type: integer}}, required: [port]}
cases:
  - name: a valid file
    env: {}
    files:
      /etc/app/main/main.json: '{"port": 8080}'        # text
      /etc/app/tls/tls.crt: {fixture: valid.crt}        # a file in fixtures/
      /etc/app/blob.bin: {base64: "/v8A"}               # bytes
    expect:
      main: {port: 8080}
```

- **`files`** go with `env` cases only. The content is a string, or one of
  `{text: ...}`, `{base64: ...}` and `{fixture: name}`. Overlay files are
  given the same way, at the overlay's `path`.
- **`expect`** may name file inputs: a `config` file's expected value is
  its data, a `text` file's its text, and any other file input's `true`.
  A file input the case writes no file for is derived as `null`; one it
  writes a file for must be in `expect`.
- **`errors`** may name a variable, a file input or an overlay (for an
  overlay file that does not parse).
- With **`profiles`**, a variable the case does not list in `expect` is
  derived from the selected profile's default, then its own: the selector
  from `env` (or `values`), else `profiles.default`. A variable an overlay
  sets must be listed in `expect`.

A profile case is an ordinary `env` or `values` case: the contract carries
the profile files' values, and `env` sets the selector, as in
`load/profiles.yaml`:

```yaml
profiles:
  selector: APP_ENV
  default: Production
  defaults:
    Production: {WAREHOUSE_URL: https://warehouse.internal, PAGE_SIZE: 50}
cases:
  - name: the selector unset uses profiles.default
    env: {}
    expect: {WAREHOUSE_URL: https://warehouse.internal, PAGE_SIZE: 50}
```

An overlay case writes the overlay's file, as in `load/overlays.yaml`:

```yaml
overlays:
  platform: {format: json, path: /app/config/platform.json, keySeparator: ":"}
cases:
  - name: the overlay beats the profile
    env: {}
    files:
      /app/config/platform.json: '{"Catalog": {"PageSize": 30}}'
    expect: {CATALOG__PAGESIZE: 30}
```

To change the certificate fixtures, edit `gen/main.go` and run
`go run ./conformance/gen` from the repository root; its tests fail if
`fixtures/` is not what it writes, and 60 days before any certificate
meant to be valid expires.

## Running the suite in an SDK

Each SDK has a runner in its own test suite. It needs the SDK's
**contract-first mode** (SPEC §11.2, item 11): validate an environment
against a contract given as JSON, with no in-language declaration,
returning typed values.

SDK CI already checks out docuconf-go `main`; the runner reads
`conformance/cases.json` from that checkout. Locate it with
`DOCUCONF_CONFORMANCE` (the path to `cases.json`), falling back to
`../docuconf-go/conformance/cases.json` for local runs, and fail (not skip)
when `DOCUCONF_REQUIRE_CONFORMANCE=1` and the file is missing.

`cases.json` looks like this:

```json
{
  "version": 1,
  "cases": [
    {
      "id": "int/below min",
      "source": "load/int.yaml",
      "requires": [],
      "contract": {"apiVersion": "docuconf.dev/v1alpha1", "kind": "ConfigContract", "metadata": {...}, "vars": {...}},
      "env": {"PORT": "0"},
      "errors": [{"var": "PORT", "code": "out_of_range"}]
    },
    {
      "id": "files_config/a valid json file",
      "source": "load/files_config.yaml",
      "requires": ["files"],
      "contract": {"apiVersion": "docuconf.dev/v1alpha1", "kind": "ConfigContract", "metadata": {...}, "vars": {}, "files": {...}},
      "env": {},
      "files": {
        "/etc/app/main/main.json": {"text": "{\"port\": 8080}"},
        "/etc/app/keystore/keystore.p12": {"base64": "MIIG..."}
      },
      "expect": {"main": {"port": 8080}, "settings-json": null}
    }
  ]
}
```

For every case:

1. **Skip** it only if `requires` holds a tag the SDK does not support,
   and report the number skipped. The SDK's README lists its unsupported
   tags. Treat a tag the runner does not know as unsupported: skip the
   case, never run it, so that a new tag does not break an SDK written
   before it. Keep a list of the tags the SDK supports, not of the ones
   it lacks.
2. **Write the files and load.** Make a new, empty directory and write
   each entry of `files` under it at its path (`/etc/app/main/main.json`
   becomes `<dir>/etc/app/main/main.json`), decoding `base64` content.
   Load `contract` with the contract-first mode, using `env` plus
   `DOCUCONF_FILE_ROOT=<dir>` as the whole environment: no process
   environment, no `.env` file, nothing else from the disk. Set the file
   root for every case, files or not, so no case reads the machine's own
   files. `contract` has every default filled in (`required: false`,
   `encoding: "csv"`, `separator: ","`, ...), and may hold `files`,
   `profiles` and `overlays`.
3. If the case has **`expect`**, loading succeeds, and every variable's
   typed value, converted to JSON, equals `expect[name]`:
   - absent optional variables are `null`;
   - `duration` is the canonical Go form: units `h`, `m`, `s`, `ms`, `us`,
     `ns`, each at most once, zero units omitted, `0s` for zero (`1m30s`,
     `1s500ms`);
   - `int` compares exactly (cases hold 64-bit values; parse `expect` with
     a big-number-safe JSON reader where the language needs one);
   - `float` compares numerically (`3` equals `3.0`);
   - `list` and `keySet` are arrays (a key set's keys in order), `json`
     any JSON value, everything else a string or bool;
   - file inputs: a `config` file is its data as JSON (compare numbers
     numerically), a `text` file its text, and a `tls`, `caBundle`,
     `keystore` or `binary` input `true`; an absent optional file is
     `null`.
4. If the case has **`errors`**, loading fails, and the set of
   (input, code) pairs reported equals `errors`, in any order. The input
   (the `var` field) is a variable, a file input, or an overlay. No error
   message, and nothing written to the termination log, may contain the
   raw `env` value of a variable whose contract entry has `secret: true`.

Report each failing case by `id`, so a failure points at its YAML source.

## Capability tags

| Tag | Meaning | SDKs that may skip it |
| --- | --- | --- |
| `int64` | The host holds every 64-bit integer as an integer. | JavaScript-runtime SDKs (T3 Env, Gleam on JavaScript) |
| `json-schema` | Contract-first mode validates `json` values against the variable's JSON Schema. | Any SDK without a JSON Schema validator, documented in its README |
| `key-set` | The `keySet` type (SPEC §4.3), in `load/key_set_type.yaml`. | Transitional: an SDK that does not have the type yet. Every SDK MUST support it by `v1beta1`. |
| `deprecated` | Deprecated inputs (SPEC §4.2): a deprecated variable that is set still loads, in `load/deprecated.yaml`. | Transitional: an SDK that does not read `deprecated` yet. Every SDK MUST support it by `v1beta1`. |
| `files` | File inputs (SPEC §4.6, §11.2 item 7), in `load/files_config.yaml` (config files in json, yaml and toml), `load/files_tls.yaml` (TLS key pairs, CA bundles, PKCS#12 keystores) and `load/files_text.yaml`. | Transitional: an SDK whose contract-first mode does not load files yet. Every SDK MUST support it by `v1beta1`. |
| `profiles` | Profiles (SPEC §4.4), in `load/profiles.yaml`: the selector, `profiles.default`, profile defaults under the environment. | Transitional. Every SDK MUST support it in contract-first mode by `v1beta1`, even on a host that has no profile files of its own. |
| `overlays` | Config-file overlays (SPEC §4.7), in `load/overlays.yaml`: the layer order base, profile, overlay, environment, native values, and bad overlay values. Its cases also require `profiles`. | Transitional, as `profiles`. |
| `strict-parsing` | The exact parsing rules of SPEC §5, in `load/strict.yaml`: `bool` is only `true` or `false` in any case (never `1`, `t`, `yes`, `on`), `int` only decimal digits with an optional sign (never `0x10`, `1_000`, `1e3`), `float` only decimal (never hex, `inf`, `.5`), durations only their encoding's grammar, and nothing is trimmed, including `csv` items. | Transitional: an SDK whose host library is still more lenient than the spec. Every SDK MUST support it by `v1beta1`. |

The transitional tags let the suite gain cases for a new feature while
SDKs written before it stay green. When every SDK supports a feature, or
at `v1beta1` at the latest, its tag is removed from the cases.

## Export

Each SDK checks its contract export against the shared fixture (SPEC
§11.2 item 3):

1. Declare the inputs in `export/fixture.yaml` in the SDK's own
   declaration API, with each description and details where the language
   documents a setting.
2. Export the contract with `metadata.name: docuconf-fixture` and
   `appVersion: "1.0.0"`, to a file such as `exported.cue` (or the
   contract as JSON).
3. Run, from the SDK's CI with the docuconf CLI installed:

   ```sh
   docuconf conformance export --golden ../docuconf-go/conformance/export/golden.cue exported.cue
   ```

   It exits 0 when the two match as data, and otherwise prints one line
   per difference, by path, and exits 1.

The comparison unifies both contracts with the meta-schema, so a field
left at its default equals one written out. It ignores
`metadata.generator`, every `encoding` and `configKey`, and a `separator` unless both
contracts use `csv`. Numbers compare by value, and a JSON Schema compares
without `title`, `$schema`, `$id`, `$comment` and `examples`, with
`required` as a set. Everything else must match, including canonical
durations and the order of lists. The Go SDK keeps its export of the
fixture in `testdata/conformance-export.cue`, and the CLI's tests compare
it with the golden contract.

## Scope

The suite covers variables: every type, encoding and constraint, the
exact parsing rules, required and optional values, empty values, secrets
(including key sets: the `keySet` type in `key_set_type.yaml`, and the
older secret list convention in `key_set.yaml`), deprecated variables,
unresolved injector references, and aggregate error reporting. It covers
file inputs (config, TLS, CA bundle, keystore and text files), profiles
and config-file overlays, and contract export through the fixture in
`export/`. Not yet covered: `binary` files beyond export, JKS keystores,
`reload: watch`, and profiles and overlays in the export fixture.
